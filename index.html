Module 01

Why does test access exist at all?

Before any acronyms: a modern chip is full of things that need to be reached from the outside, and it only has a handful of pins to reach them with.

The chip
Click the button — watch six internal blocks each try to fight their way to a handful of external pins.
Why this matters: Wiring every internal block straight to a package pin doesn't scale — pins are expensive, and most of these signals are only needed rarely, during test or debug. Chips need a shared, standardized, serial path instead of one wire per signal. That shared path is what JTAG — and later IJTAG — provide.

Module 03

The four wires: TCK, TMS, TDI, TDO

Every JTAG interaction, no matter how complex, is built from just these signals.

SignalRole
TCKTest Clock — every JTAG action happens on its edge
TMSTest Mode Select — steers the TAP state machine, 1 bit per TCK
TDITest Data In — serial data going into the chip
TDOTest Data Out — serial data coming out of the chip
TRSTOptional async reset of the TAP (many designs use TMS-based reset instead)
Try it — shift a value through a 4-bit register
TDI value queued next: 1 · TDO out: –
Beginner view: think of the register as a bucket brigade. Each clock pulse, everyone passes their bit one seat to the right; a new bit enters on the left (TDI), and whatever falls off the right end is TDO.
Technical view: this is a simple shift register modelling the Shift-DR/Shift-IR TAP state. On each TCK rising edge while in a shift state, the register shifts one position toward TDO and samples TDI into the LSB (or MSB depending on chain convention).

Capture · Shift · Update

Capture loads live values into the register; Shift moves bits toward TDO while new bits enter from TDI; Update pushes the shifted-in value out to where it takes effect.

Boundary scan — catching a board-level fault
Boundary cells at each pin can drive a known value (EXTEST) and the neighbor chip's cell can sample what actually arrived (SAMPLE) — catching open/short board faults without any functional traffic.

Module 08

SIB — the Segment Insertion Bit

Think of a SIB as a locked gate on a hallway. Closed, you walk straight past it. Open it, and a whole side-room becomes part of your path.

A SIB is itself a 1-bit register in the scan path. Its value, established through capture/shift/update like any other bit, determines whether a downstream segment is included in the active scan chain.

The gate
0
Step through Capture → Shift → Update to actually change the SIB's committed value — clicking the gate doesn't just toggle a mux.
Effect on the active path
active bypassed
SIB = 0 → downstream segment not inserted, scan path stays short.
SIB = 1 → downstream segment inserted, instrument becomes reachable, scan path gets longer.

Module 10

ICL describes the map. PDL describes the trip.

ICL — Instrument Connectivity Language

"What exists, and how is it wired?" ICL describes modules, ports, scan registers, SIBs, instruments, and the connections between them.

// simplified educational example
ScanRegister sib1 { length 1; SIB { ... } }
ScanInterface mbist_if {
  ScanInPort si; ScanOutPort so;
}
Instance mbist_inst of MBIST {
  connect(mbist_if.si, sib1.so);
}

Simplified for teaching — not literal Accellera ICL / IEEE 1687 syntax.

PDL — Procedural Description Language

"What operation do I run, in what order?" PDL describes the procedure for using an instrument: open the right SIB, write control, wait, read status.

// simplified educational example
iProcedure run_mbist {
  iWrite sib1 = 1;       // open SIB
  iWrite mbist.CONTROL = START;
  iApply;
  iRead  mbist.STATUS == PASS;
}

Simplified for teaching — not literal IEEE 1687 PDL syntax.

Analogy: ICL is the map of the building — rooms and hallways. PDL is the instructions for walking to a specific room and flipping a specific switch. A retargeting tool reads both to figure out how to reach an instrument once it's buried inside a bigger integrated chip.
